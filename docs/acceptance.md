# 검증과 완료 조건

문서 계획만 작성한 상태와 앱 구현 완료를 구분한다. 검증 결과에는 실행 명령, 통과/실패, 남은 문제를 적는다.

## A: 백엔드/DB

- [ ] `architecture.md`의 Windows 가상환경/설치/seed/uvicorn 명령으로 새 환경에서 실행된다.
- [ ] 재실행 가능한 seed가 20권을 만들며 기존 주문/재고를 임의로 초기화하지 않는다.
- [ ] 제목·저자·출판사 검색, 모든 카테고리/정렬, 상세 조회가 실제 DB로 동작한다.
- [ ] 세션 장바구니 추가/수정/삭제/합계와 새로고침 유지가 정확하다.
- [ ] 품절·재고 초과·비정수/0/음수 수량·빈 주문이 차단된다.
- [ ] 주문 항목의 제목/단가는 주문 시점 값으로 보존된다.
- [ ] 재고 1개를 두 연결에서 주문하면 하나만 성공하고 재고가 음수가 되지 않는다.
- [ ] 재고 부족/저장 오류 시 주문·항목·재고 변경이 모두 rollback된다.
- [ ] 서버가 클라이언트 가격을 신뢰하지 않으며 다른 세션의 주문 조회는 차단된다.
- [ ] CSRF 오류가 차단되고, 완료 후 새로고침은 새 주문을 만들지 않는다.
- [ ] `python -m pytest tests/backend` 통과. 임시 DB를 사용하고 실제 로컬 DB를 지우지 않는다.

## B: 화면/사용 흐름

- [ ] 카드 표지·제목·가격·할인율·샘플 평점이 표시된다.
- [ ] PC 5열 / 태블릿 3열 / 모바일 2열과 모바일 카테고리 메뉴가 동작한다.
- [ ] 홈부터 상세·장바구니·checkout·완료까지 실제 서버에서 구매할 수 있다.
- [ ] 검색 없음·품절·빈 장바구니·재고 변경·폼 오류 화면을 확인했다.
- [ ] 검색 입력과 버튼, 수량 입력, 폼 label, 키보드 포커스, 표지 대체 텍스트를 확인했다.
- [ ] 가짜 버튼/깨진 링크/가로 넘침이 없으며 테스트 주문임을 명확히 표시한다.
- [ ] `docs/ui-verification.md`에 1440/768/390px 검증 결과와 남은 문제를 기록한다(구현 때 작성).
